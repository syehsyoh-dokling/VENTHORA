Upload datasetany file, any layout: VENTHORA's agent reads it and files the data where it belongs

1 · What you do
  1. Choose one or more files: Excel, CSV, JSON, Word, PDF, HTML, an e-mail or plain text.
  2. Leave Auto-detect on, or pick the kind of data.
  3. Press Read the file(s), check the column matches, press Preview.
  4. Press Commit when the preview looks right.
2 · What VENTHORA does
  • Reads the file and decides what it holds: vendors, people, POs, budgets…
  • Matches each column to a VENTHORA field and cleans the values (amounts, dates, IBANs).
  • Preview: shows what would be created, updated or rejected, and why. Nothing is written yet.
  • Commit: writes the records through the same checks as entering them by hand.
3 · The result
  • Each record lands on its own page (Payees, Offices, Purchase orders…), with a link after Commit.
  • A row that fails a check is rejected with the reason; the rest go in.
  • A vendor's new or changed bank details still wait for a call-back before any payment.
  • Every commit is in the audit log: who, which file, how many records.
4 · Why use it
  • You: no API, no reformatting, no typing records one by one; the file as your old system exports it.
  • VENTHORA: starts on the company's real data instead of placeholders, checked on the way in.
5 · Limits and who reads the file
  • checking the AI model…
  • A one-time import, not a live link: upload again when the data changes, or use App Integration for a sync.
  • Photos, scans and old .xls files cannot be read; upload the PDF with text, .xlsx or CSV.
  • Up to 15 MB and 5,000 rows per file; Excel reads the first sheet that has data.
  • The file itself is not stored: it is held in memory until Commit, then only the committed records are kept.

How email reaches VENTHORAthree ways; use one or all of them

1 · A mail service pushes it
Suppliers write to, or copy, an address the company sets for VENTHORA. The mail service (Postmark, Mailgun, SendGrid, Cloudflare, …) posts each email the moment it arrives. Realtime.
2 · VENTHORA reads an inbox
Connect an existing mailbox (Gmail, Microsoft 365, Yahoo, iCloud, Zoho, any IMAP). VENTHORA reads new mail on a schedule, every minute by default, and marks or moves what it read.
3 · Staff order payments by email
People ticked below may ask VENTHORA to pay a registered vendor by email. The order joins the queue and a different person approves it; email never pays by itself.

AI model

How the model is used

  • It reads emails, PDFs and the inbox, and proposes values with the words it read them from.
  • Code keeps a value only if that quote is in the source and the value is inside it; otherwise it is dropped.
  • When the model and the rules disagree, a person decides. It never sets an amount or moves money.
  • A hosted provider receives the email and PDF text, so it needs your confirmation first.
  • Keys are kept on this machine (git-ignored) and never shown again: only their last four characters.
  • Nothing saved here: MODEL_ENDPOINT / MODEL_NAME in .env apply.

Delegation of Authority (DoA)

What the FCO delegates to VENTHORA's agent, by kind of payment. Internal payments are the organisation's own recurring obligations: the FCO sets one standing payment instruction per cost category, and on the pay date the agent pays on its own what the instruction allows. External payments are invoices from vendors and short-term specialists. Anything outside the delegation is prepared for a person; some things are never executed. Every payment still passes the treasury limits and controls.
loading…
The mandate is the authority the finance team gives VENTHORA's agent. Inside it the agent checks, plans and pays on its own; outside it, it stops and asks a person. It has three parts: the checks every request must pass before anything is payable, the permissions and safeguards with their limits, and the approval policy for everything else. Every run on the Operations page starts from this standing mandate and records exactly what was granted. One role holds the authority to change it.
